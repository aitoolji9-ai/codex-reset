# Codex 리셋 알림 코드

Codex 리셋 공지의 **예정 / 완료 기록**을 감지하는 작은 Python 코드입니다.
특정 채널이나 메신저에 종속되지 않습니다. 사용자가 원하는 SNS·메신저·이메일·앱에 발송 부분만 연결해 사용하세요.
조회·판별·기본 출력에는 AI를 호출하지 않아 AI 토큰을 사용하지 않습니다.

## 핵심 파일

| 파일 | 역할 |
| --- | --- |
| `reset_notifier.py` | 공지 해석, 20분/5분 간격 결정, 한국시간 메시지, 중복 방지 |
| `transport.py` | 정보원 조회 |
| `cli.py` | 계속 확인하는 실행 루프 |
| **`notify.py`** | **원하는 곳으로 보내도록 수정할 함수 `send(notification)`** |

기본 `send()`는 알림을 JSON 한 줄로 화면에 출력합니다. 메신저 계정·채널·토큰은 들어 있지 않으며 외부로 발송하지 않습니다. 특정 메신저의 완성된 연동 코드를 제공하는 패키지는 아닙니다.

## 시작

Python 3.9 이상과 Git이 필요합니다. 기본 실행은 표준 라이브러리만 사용합니다.

```sh
git clone https://github.com/aitoolji9-ai/codex-reset.git
cd codex-reset
python3 cli.py --dry-run --snapshot tests/fixtures/api-live.json
python3 cli.py
```

- 첫 명령은 합성 데이터로 메시지를 확인하며 원장·외부 발송을 변경하지 않습니다.
- `python3 cli.py`는 실제 정보원을 계속 조회하고 **새 알림을 화면에 출력**합니다. Ctrl+C로 종료합니다.
- 최초 실행은 현재 기록을 기준선으로 저장해 과거 알림을 보내지 않습니다.
- `--once`는 한 번 조회, `--dry-run`은 실제 정보원 조회·검사만 수행합니다.
- 중복 방지 원장은 기본 `state/ledger.json`에 저장합니다. `--state-dir`로 바꿀 수 있습니다.

현재 파일 잠금은 Unix `fcntl`을 사용합니다. macOS·Linux에서 실행하며 Windows는 WSL 또는 Linux Docker를 사용하세요. 기기가 꺼지거나 잠들면 조회도 멈춥니다.

## 원하는 메신저에 연결

`notify.py`의 **`send(notification)` 한 곳**을 자신이 사용하는 발송 코드로 바꾸면 됩니다.

전달되는 데이터:

```python
notification['text']     # 한국시간·출처 링크가 포함된 전체 메시지
notification['title']    # 예정 / 완료 기록 / 시각 확인 필요
notification['id']       # 공지 식별자
notification['phase']    # scheduled 또는 landed
notification['sources']  # 출처 이름과 URL 목록
notification['event']    # 정규화된 원본 정보(시각·종류·대상 등)
```

`text`는 일반 텍스트이므로 메신저의 Markdown·HTML 모드를 켜면 해당 서비스 방식으로 이스케이프하세요. `event`의 시각은 계산용 UTC이며 메시지 표시는 한국시간입니다.

**발송 함수의 계약:** API 응답의 성공을 확인한 뒤 정상 반환하고, 실패하거나 결과가 불명확하면 예외를 발생시키세요. 요청에는 시간 제한을 두세요. 중복 방지 키를 지원하는 API에는 `id + phase`를 사용할 수 있습니다. 인증정보와 수신 대상은 각자의 환경변수 등 로컬 설정에서 읽으세요. `.env`를 사용하는 기본 로더는 `STATE_DIR`만 읽으므로 추가 키가 필요하면 로더도 명시적으로 수정하거나 발송 함수에서 별도 설정을 읽으세요.

화면 출력도 원장에는 처리 완료로 기록됩니다. 메신저 연결 전 시험은 `--dry-run`으로 하세요. 이미 출력한 알림을 연결 후 다시 보내지는 않습니다. 여러 목적지에 보내는 경우 목적지별 성공 상태를 관리하도록 확장해야 합니다. 일부만 성공한 상황에서 모두 재발송하지 마세요.

이전 Slack 전용 버전에서 갱신한다면 먼저 기존 실행을 종료하고 발송 함수를 연결하세요. `.env`의 기존 `SLACK_WEBHOOK_URL`·`SLACK_THREAD_TS` 키는 새 로더에서 지원하지 않으므로 제거하거나 자신의 발송용 설정으로 옮기세요. 기존 `state/ledger.json`은 그대로 유지합니다.

AI에 적용을 맡길 때는 다음처럼 요청하면 됩니다.

> 이 저장소를 읽고 내가 사용하는 [메신저 이름]의 [수신 대상]으로 리셋 알림을 보내도록 notify.py를 연결해줘. 내 운영체제에 맞게 설치하고 API 성공 응답·실패·중복 방지를 검증해줘. 인증정보는 저장소나 채팅에 노출하지 말고 로컬 설정으로 관리해줘. 기존 알림 원장을 보존하고 중복 실행하지 마.

## 알림 예시

```text
⏰ Codex 리셋 예정
예정: 26.10.29 03:00 (한국시간)
사용량 한도 리셋 · 대상: 전체
예정 안내이며, 완료가 확인되면 별도로 알립니다.
출처: WhenReset https://whenreset.dev · 티보 X 원문 [원문 URL]
```

완료 기록은 `✅ Codex 리셋 완료 기록`으로 구분하며 완료 기록 시각·발견 시각·지연 시간을 표시합니다. `Banked Reset`은 `리셋권 지급`으로 표시합니다.

## 확인 주기와 중복 방지

- 기본 20분, 예정 시각 30분 전부터 5분. 같은 ID의 완료를 확인하거나 예정 시각 1시간 후가 되면 기본 주기로 복귀합니다.
- 처리 후 대기하므로 조회·발송 시간은 간격에 더해집니다. 빠른 확인 구간의 시작·종료 경계에서는 남은 시간만 기다립니다.
- 예고가 피드에서 일시적으로 사라져도 원장으로 유지합니다. ID가 다른 완료를 같은 예고로 추측하지 않습니다.
- 예정 시각이 지났다는 이유로 완료를 만들어내지 않습니다. API의 완료 기록이 필요합니다.
- 예고·완료는 각각 한 번 처리하고 재시작해도 이력을 유지합니다.
- 발송 전 `sending`, 정상 반환 후 `sent`, 예외 시 `unknown`을 기록합니다. 결과 불명확 시 자동 재발송 없이 멈춥니다.
- `sending`/`unknown` 상태는 실제 수신 내역을 대조한 뒤 복구하세요. 원장을 백업하고 확인된 항목만 보완하며 원장 전체를 지우지 마세요.

정보원은 [WhenReset 공개 API](https://whenreset.dev/api/resets)입니다. OpenAI 공식 API가 아니며 개인 계정의 실제 리셋 적용 여부를 조회하지 않습니다. 원문 링크·정보원 반영 지연과 누락·조회 간격을 고려하세요.

## 검증·선택 설치

```sh
python3 -m unittest discover -s tests -v
```

합성 데이터와 모의 발송으로 시간 전환·메시지·재시작·실패·중복 방지를 검사합니다. 실제 메신저 연결은 본인이 추가한 발송 함수로 따로 검증하세요. GitHub Actions는 macOS/Linux 시험만 실행하며 알림을 상시 운영하지 않습니다.

`sh install.sh`는 선택적으로 가상환경과 비공개 `.env`를 만듭니다. Docker 예제와 Linux 사용자 systemd 예제도 포함되어 있습니다. 자신의 경로·의존성·발송 함수에 맞게 수정하세요. Docker는 수정한 `notify.py`를 포함해 다시 빌드해야 합니다. 서비스로 전환할 때 기존 실행을 먼저 멈추고 같은 원장을 이어 사용하세요. 실행 환경별 자동 시작은 별도로 설정해야 합니다.
